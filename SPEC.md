# Spec: автономный браузерный AI-агент

Статус: реализовано. Спека фиксирует исходный план; решения, принятые после неё (Sonnet 5 вместо
Opus 5, провайдер OpenRouter, второй вход через MCP, ожидание готовности страницы, свёртка
оверлеев, отмена задачи), описаны в журнале решений README.md.

## Context

Тестовое задание требует агента, который принимает текстовую задачу в терминале и
автономно решает её в видимом браузере, останавливаясь только когда нужна информация
от человека или когда задача выполнена. Оценивают не знание библиотек, а архитектуру:
как извлекается состояние страницы, как удерживается контекст, как агент восстанавливается
после неудачных действий и как он защищён от необратимых действий.

Главное ограничение ТЗ: агент должен решать **любую новую задачу**. Нельзя зашивать шаги
сценариев, селекторы и подсказки про устройство конкретных сайтов. Это переводит задачу
из «автоматизируй три сценария» в «построй универсальный контур наблюдение-решение-действие».

## Proposed Change

Один процесс Node: REPL в терминале + видимый Chrome под Playwright + агентный цикл на
Claude. Три роли модели, две из них - специализированные суб-агенты.

```
  терминал (REPL)                    процесс Node                        Chrome (видимый)
  --------------                     ------------                        ----------------
  You: закажи хот-дог  ──▶  ┌────────────────────────┐
                            │ agent loop (opus-5)    │
        🔧 tool call   ◀──  │  наблюдение -> решение │
                            │         │              │
                            │         ▼ действие     │──▶ Playwright ──▶ страница
                            │  ┌──────────────┐      │                      │
                            │  │ security gate│      │◀── дистилляция ◀─────┘
                            │  └──────┬───────┘      │
                            │         │ high risk    │
  Подтвердить? [y/N] ◀──────┼─────────┘              │
                            │                        │
                            │  sub-agents (haiku):   │
                            │   - query_page         │
                            │   - risk classifier    │
                            └────────────────────────┘
```

#### Контракт инструментов

Каждое действие возвращает свежее наблюдение в том же результате. Это убирает лишний
round-trip «сделал -> посмотри» и держит один шаг = один вызов модели.

```ts
type Observation = {
  url: string;
  title: string;
  elements: string;   // "[e3] searchbox \"Поиск\"" построчно
  text: string;       // innerText, обрезанный до 3000 символов
  tabs: number;
  note?: string;      // напр. "открылась новая вкладка", "появился диалог"
};

type ToolResult =
  | { ok: true;  message: string; observation: Observation }
  | { ok: false; error: ErrorCode; message: string; observation: Observation };

type ErrorCode =
  | "stale_ref"        // рефа нет в текущем снапшоте
  | "not_visible"      // элемент есть, но не виден даже после скролла
  | "intercepted"      // клик перехвачен оверлеем, в message - кто именно
  | "timeout"
  | "declined";        // человек отклонил действие в security-гейте
```

Инструменты (14):

| Инструмент | Аргументы | Мутирует | Назначение |
|---|---|---|---|
| `navigate` | `url` | да | переход по URL |
| `go_back` | — | да | назад по истории |
| `observe` | — | нет | пересобрать наблюдение |
| `click` | `ref`, `intent` | да | клик по элементу |
| `type_text` | `ref`, `text`, `press_enter` | да | ввод текста |
| `select_option` | `ref`, `value` | да | выбор в select |
| `scroll` | `direction`, `ref?` | нет | прокрутка |
| `wait` | `seconds`, `reason` | нет | пауза |
| `screenshot` | `reason` | нет | картинка в контекст (D2) |
| `query_page` | `question` | нет | вопрос к DOM sub-agent |
| `list_tabs` | — | нет | список вкладок |
| `switch_tab` | `index` | да | переключение вкладки |
| `ask_user` | `question` | нет | вопрос человеку, цикл ждёт ответа |
| `finish` | `summary` | нет | финальный отчёт, конец задачи |

`intent` на `click` - обязательное поле: одна фраза, что агент намерен сделать и
обратимо ли это. Это вход для гейта, а не его решение.

`screenshot` отдаёт только вьюпорт, не всю страницу: JPEG q70, ширина до 1024 px.
Полностраничный скриншот весит кратно больше и вытесняет из контекста то, ради чего его
звали. Картинка живёт в истории как обычное наблюдение и вычищается прунингом на общих
основаниях - иначе три скриншота за прогон съедят весь выигрыш дистилляции.

#### Дистилляция (browser/distill.ts)

Функция исполняется через `page.evaluate` в контексте страницы и возвращает готовые строки.
Правила, подтверждённые на POC:

1. Снять `data-agent-ref` со всех элементов (рефы живут один снапшот).
2. Обойти `document`, рекурсивно заходя в `shadowRoot`.
3. Элемент берётся, если интерактивен (`a`, `button`, `input`, `select`, `textarea`,
   ARIA-роль из списка интерактивных, `onclick`, `tabindex != -1`) и видим
   (rect >= 2x2, не `display:none`, не `visibility:hidden`, не `opacity:0`).
4. Роль выводится из тега/`type`/атрибута `role`; имя - первое непустое из
   `aria-label`, `placeholder`, `alt`, `title`, `value`, `innerText`, обрезается до 80 симв.
5. Проставить `data-agent-ref="eN"`, выдать строку `[eN] role "name" [state]`.
6. Отдельно вернуть `innerText` страницы, обрезанный до 3000 символов.

Соседние фреймы: обход повторяется для каждого `page.frames()`, рефы получают префикс
фрейма (`f1:e7`), действия резолвятся в нужный фрейм.

#### Управление контекстом (три уровня)

| Уровень | Механизм | Эффект |
|---|---|---|
| 1. У источника | дистилляция | 430 954 -> 2 321 симв., 186x |
| 2. Клиентский прунинг | в истории остаются полными последние 3 наблюдения; более старые `tool_result` заменяются на `[observation pruned: "<title>", N элементов]` | история растёт линейно и медленно |
| 3. Серверный | `context_management: {edits:[{type:"clear_tool_uses_20250919"}]}`, beta `context-management-2025-06-27` | страховка на очень длинных прогонах |

Плюс prompt caching: системный промпт и определения инструментов стабильны и кешируются,
volatile-часть (наблюдения) идёт после последнего breakpoint. В терминал по каждому шагу
печатается `in/out/cache_read` токены - расход виден на видео.

#### Sub-agents (agent/subagents.ts)

Оба на `claude-haiku-4-5`, оба вызываются из харнесса, их вход и выход не попадают
в основную историю.

**query_page.** Вход: вопрос агента + полная дистилляция + `innerText` + при
необходимости `outerHTML` поддерева. Выход: короткий текстовый ответ. Нужен там, где
сжатое наблюдение недостаточно: «какие хот-доги в выдаче и какие у них кнопки добавления»,
«что показывает счётчик корзины».

**risk classifier.** Вход: описание элемента, `intent` агента, url и title страницы.
Выход через structured output:

```ts
{ risk: "low" | "medium" | "high", reason: string, reversible: boolean }
```

#### Security gate (agent/security.ts)

Гейт живёт в харнессе и выполняется до действия, независимо от того, что агент объявил.

1. Не мутирующие инструменты (`observe`, `scroll`, `wait`, `screenshot`, `query_page`,
   `list_tabs`) проходят без классификации.
2. Для мутирующих вызывается risk classifier. Результат кешируется по
   `(имя элемента + intent)`, чтобы не платить за повтор.
3. `high` -> цикл останавливается, в терминал печатается что именно собирается сделать
   агент и почему это признано необратимым, запрашивается `y/N`. Отказ возвращается агенту
   как `{ok:false, error:"declined"}` - агент обязан продолжить другим путём, а не молча встать.
4. Текст страницы в промпте обёрнут в разделители и помечен как недоверенные данные.
   Инъекция со страницы не может ни снять гейт, ни подменить `intent`: решение принимает
   харнесс, а не модель, читающая страницу.

#### Обработка ошибок (browser/actions.ts)

| Ситуация | Поведение |
|---|---|
| рефа нет в текущем DOM | `stale_ref` + свежее наблюдение, агент переосмысливает |
| элемент за пределами вьюпорта | `scrollIntoViewIfNeeded`, одна повторная попытка |
| клик перехвачен | `intercepted`, в `message` - имя перехватившего элемента |
| открылась новая вкладка | автоматически подхватывается, `note` в наблюдении |
| нативный диалог | `page.on("dialog")`, диалог не блокирует процесс, попадает в `note` |
| таймаут навигации | `timeout` + наблюдение того, что успело отрисоваться |
| 3 неудачи подряд по одному рефу | принудительное `observe`, реф выводится из игры |
| 40 шагов без `finish` | цикл останавливается, агент отчитывается о том, что успел |

#### Агентный цикл (agent/loop.ts)

Ручной streaming-цикл, не tool runner: нужен контроль над историей (прунинг), над
гейтом между решением и действием, и над печатью вызовов в терминал.

```ts
const stream = client.messages.stream({
  model: "claude-opus-5",
  max_tokens: 64000,
  thinking: { type: "adaptive", display: "summarized" },
  output_config: { effort: "high" },
  system: SYSTEM_PROMPT,          // стабильный префикс, кешируется
  tools: TOOLS,                   // стабильный набор, кешируется
  messages,
});
const message = await stream.finalMessage();
```

Первое наблюдение агент получает до первого своего хода: при старте задачи харнесс
дистиллирует текущую вкладку и кладёт её в первое user-сообщение. Это важно именно из-за
persistent session - пользователь мог оставить открытой нужную страницу, и агент обязан
это увидеть, а не начинать с `about:blank`.

Бюджет задержки на шаг: действие в браузере 0.3-2 с, дистилляция менее 100 мс,
risk classifier на haiku 0.5-1.5 с и только для мутирующих действий, основной вызов
opus-5 - остальное. Классификатор добавляет к мутирующему шагу до 1.5 с; при кеш-попадании
по `(имя элемента + intent)` - 0 с.

Причины выбора: `claude-opus-5` - многошаговое рассуждение и планирование в моменте;
adaptive thinking с `display: "summarized"` - видно ход мысли на видео;
`effort: "high"` - агентная работа; streaming - длинные ответы не упираются в HTTP-таймаут.

#### Терминальный вывод (ui/render.ts)

Формат повторяет то, что видно на скриншотах кандидата с оффером:

```
🔧 Using tool: type_text
   Input: { "ref": "e3", "text": "хот-дог", "press_enter": true }
   Result: Typed text into [e3] searchbox "Поиск"
🧠 DOM Sub-agent: Processing query...
   Result: В выдаче 3 хот-дога, кнопки "+" у каждого
🔒 Security gate: HIGH - оформление заказа необратимо
   Подтвердить действие? [y/N]
```

## Acceptance Criteria

1. `npm run dev` поднимает видимый Chrome и REPL; браузер не headless.
2. Ручной логин пользователя переживает перезапуск процесса: после `launchPersistentContext`
   на тот же профиль сессия сохраняется без повторного входа.
3. Агент решает задачу «найди хот-дог и добавь в корзину» на lavka.yandex.ru, ни разу
   не получив в промпте ни одного селектора, URL-пути или названия кнопки этого сайта.
4. Grep по `src/` не находит ни одного литерала с доменом целевого сайта, CSS-селектором
   сайта или текстом его кнопок. Единственный домен в коде - `about:blank`. URL, по которым
   ходит агент, приходят либо из текста задачи пользователя, либо из `href` элементов,
   прочитанных со страницы в рантайме.
5. Raw HTML никогда не попадает в основной контекст: в `messages` уходит только
   `Observation`. Текстовая часть наблюдения укладывается в остаток бюджета в
   8 000 символов после списка элементов, но сам список не обрезается никогда:
   по нему агент действует, и спрятанный элемент - это скрытый тупик. На тяжёлых
   страницах вроде главной hh.ru (204 элемента) наблюдение выходит за 8 000 за счёт
   элементов, и это принято осознанно.
6. На задаче из 20+ шагов в `messages` одновременно присутствуют не более 3 полных
   наблюдений, остальные - заглушки. Проверка: при сопоставимых по размеру страницах
   input-токенов на шаге 20 не больше, чем на шаге 8.
7. Действие, классифицированное как `high`, не выполняется без ответа `y` в терминале.
   Проверяется отклонением: после `N` действие не выполнено, агент продолжает работу.
8. Прогон с подменённым рефом (искусственно устаревшим) возвращает `stale_ref` и агент
   восстанавливается без падения процесса.
9. `ask_user` останавливает цикл, ответ человека попадает в историю, цикл продолжается.
10. `finish` печатает отчёт: что сделано, что не сделано, что осталось в корзине/ящике.
11. Тесты написаны и проходят.
12. README содержит журнал технических решений и отклонённых вариантов.

## Out of Scope

- Автоматический логин и обход капчи. ТЗ прямо допускает предварительный ручной вход.
- Заготовки под сценарии из ТЗ. Агент решает их тем же универсальным контуром или не решает.
- Кроссбраузерность. Только Chrome через `channel: "chrome"`.
- Параллельные задачи и очередь. Один REPL, одна задача за раз.
