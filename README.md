# AI Browser Agent

Автономный агент, который принимает задачу текстом в терминале и решает её в настоящем
видимом браузере: сам исследует страницу, сам решает, куда нажать, сам восстанавливается
после неудач и спрашивает человека только перед необратимым действием.

Агент не знает заранее ни одного сайта. В коде нет ни зашитых селекторов, ни путей, ни
названий кнопок, ни сценарных заготовок — как это проверить, написано ниже.

## Запуск

```bash
npm install
cp .env.example .env        # и вписать ключ, см. «Провайдер модели»
npm run dev
```

Нужен установленный Chrome: агент запускается через `channel: "chrome"`, а не на
bundled Chromium — у настоящего Chrome меньше поводов сработать антиботу.

Первый запуск откроет пустой браузер. Если задача требует аккаунта, залогиньтесь в нём
руками: профиль лежит в `.profile/` и переживает перезапуск процесса.

```
You: найди на lavka.yandex.ru хот-дог и добавь в корзину
```

## Режим MCP: через Claude Code

Второй вход в то же ядро, для запуска без API-ключа. Браузерные инструменты отдаются
как MCP-сервер, а думает и выбирает инструменты Claude Code под подпиской пользователя.

```bash
npm install
claude            # в корне проекта; .mcp.json подключит сервер browser
```

При первом запуске Claude Code спросит, доверять ли серверу `browser` из `.mcp.json`.
После этого откроется Chrome на том же профиле `.profile/`, и задачу можно писать прямо
в Claude Code.

Что переходит из основного режима без изменений: дистилляция страницы, рефы
`data-agent-ref`, обработка ошибок (`stale_ref`, перехваченный клик, новая вкладка,
нативный диалог) и security-гейт. Вопрос гейта приходит в Claude Code диалогом MCP
elicitation. Если клиент elicitation не поддерживает, гейт считает это отказом и
действие не выполняет.

Чего в этом режиме нет, и это надо понимать:

| Основной режим (`npm run dev`) | Режим MCP |
|---|---|
| Собственный агентный цикл, лимит шагов, детектор зацикливания | Цикл ведёт Claude Code |
| Прунинг наблюдений и серверный context editing | Авто-компакция Claude Code |
| Суб-агент `query_page` | Нет: ему нужен API-ключ |
| Классификатор риска + детерминированный пол | Только детерминированный пол и режим после отказа |

Поэтому архитектуру агента показывает основной режим. MCP-режим нужен, чтобы
пользоваться тем же браузерным слоем по подписке.

## Провайдер модели

Агент говорит по протоколу Anthropic Messages API. Кроме самой Anthropic его понимают
совместимые шлюзы, поэтому провайдер — это конфигурация, а не код.

| Провайдер | Что положить в `.env` | Модель по умолчанию |
|---|---|---|
| z.ai (GLM) | `ZAI_API_KEY=` ([apikey-list](https://z.ai/manage-apikey/apikey-list)) | `glm-4.6` |
| Anthropic | `ANTHROPIC_API_KEY=` ([console](https://console.anthropic.com)) | `claude-sonnet-5` + `claude-haiku-4-5` на суб-агентах |

Провайдер определяется сам: достаточно задать один ключ. Явно — через `AGENT_PROVIDER`,
модели — через `AGENT_MODEL` и `AGENT_SUB_MODEL`.

У z.ai флагманские модели (`glm-4.6`, `glm-4.5-air`) платные и без баланса отвечают
`1113 Insufficient balance`. Бесплатны Flash-модели, и они умеют tool calling, то есть
агент на них работает:

```
AGENT_MODEL=glm-4.7-flash
AGENT_SUB_MODEL=glm-4.5-flash
```

Плата за бесплатность — лимиты запросов: провайдер периодически отдаёт `429` и `529`.
Цикл это переживает (ретраи с нарастающей паузой в `src/agent/loop.ts`), но на длинной
задаче прогон заметно дольше.

Совместимость протокола не означает совместимость возможностей. Adaptive thinking,
`effort`, серверный context editing и prompt caching — расширения Anthropic; на чужом
шлюзе они либо игнорируются, либо возвращают 400. Поэтому каждая объявлена отдельным
флагом в `src/agent/provider.ts` и просто не отправляется туда, где не поддерживается.
При старте агент печатает, что именно у текущего провайдера недоступно.

На GLM это значит: нет видимого хода мысли в терминале, нет кеширования промпта (каждый
шаг оплачивается целиком) и работает только клиентский прунинг контекста. Сам цикл,
инструменты, рефы и security-гейт не меняются.

## Как это устроено

```
  терминал (REPL)                    процесс Node                        Chrome (видимый)
  --------------                     ------------                        ----------------
  You: задача текстом  ──▶  ┌────────────────────────┐
                            │ agent loop (opus-5)    │
        🔧 вызов        ◀── │  наблюдение → решение  │
                            │         │              │
                            │         ▼ действие     │──▶ Playwright ──▶ страница
                            │  ┌──────────────┐      │                      │
                            │  │ security gate│      │◀── дистилляция ◀─────┘
                            │  └──────┬───────┘      │
                            │         │ high risk    │
  Выполнить? [y/N]   ◀──────┼─────────┘              │
                            │  sub-agents (haiku):   │
                            │   query_page, risk     │
                            └────────────────────────┘
```

Один шаг агента — один вызов модели: каждое действие возвращает свежее наблюдение в том
же результате, без лишнего round-trip «сделал → а теперь посмотри».

| Файл | Отвечает за |
|---|---|
| `src/browser/distill.ts` | сжатие страницы до списка элементов с рефами |
| `src/browser/actions.ts` | действия по рефу, классификация ошибок, восстановление |
| `src/browser/session.ts` | персистентный профиль, вкладки, нативные диалоги |
| `src/agent/loop.ts` | цикл, стриминг, прунинг истории, лимиты |
| `src/agent/security.ts` | гейт подтверждения перед необратимым |
| `src/agent/subagents.ts` | DOM sub-agent и классификатор риска на haiku |
| `src/agent/prompt.ts` | системный промпт |

## Управление контекстом

Отправлять страницу в модель целиком нельзя, и дело не только в лимитах. Замеры на
`lavka.yandex.ru`:

| Представление | Размер | К raw HTML |
|---|---|---|
| Raw HTML | 433 953 симв. | 1x |
| Playwright `ariaSnapshot()` | 7 153 симв. | 60x |
| Наш список элементов | 2 321 симв. (63 элемента) | 186x |
| Наблюдение целиком (элементы + текст + метаданные) | 4 648 симв. (61 элемент) | 93x |

Две последние строки меряют разное: 186x — это только список интерактивных элементов
(сравнимо с `ariaSnapshot`), 93x — весь объект, который реально уходит в модель, вместе
с видимым текстом страницы. В контекст попадает вторая цифра.

Дальше работают ещё два уровня:

- **Клиентский прунинг** (`src/agent/context.ts`): полными в истории остаются последние
  3 наблюдения, остальные схлопываются в заглушку. Старые снимки бесполезны — рефы в них
  всё равно недействительны.
- **Серверный context editing**: `clear_tool_uses_20250919`. Включён по умолчанию и
  отключается сам, если бета недоступна аккаунту.

Плюс кеширование: системный промпт и определения инструментов стабильны за прогон, в
терминал по каждому шагу печатается `in/out/cache_read`.

## Адресация элементов без селекторов

Агент видит строки вида `[e3] searchbox "Поиск"` и возвращает реф. Рефы проставляются
проходом по DOM в рантайме (`data-agent-ref`) и живут ровно один снимок: после любого
действия они перевыдаются, а старые атрибуты снимаются. Устаревший реф даёт честную
ошибку `stale_ref` со свежим наблюдением, а не клик по случайному элементу.

Кликать по CSS-селекторам агент не может физически — такого инструмента нет.

## Security layer

Гейт живёт в харнессе, а не в модели, и состоит из трёх независимых уровней. Каждый
добавлен после того, как живой прогон пробил предыдущий.

**1. Классификатор.** Для мутирующих инструментов отдельный суб-агент оценивает риск по
описанию элемента, намерению агента, задаче и списку уже запрещённого. Ему явно сказано
судить по тому, что элемент реально делает, а не по тому, как его описал агент.

**2. Детерминированный пол.** Категории необратимых действий — трата денег, отправка
адресату, удаление, публикация, заявление от имени человека (возраст, личность, согласие) —
распознаются кодом. Классификатор может поднять оценку выше пола, опустить не может.

**3. Режим после отказа.** Если человек что-то запретил, каждое последующее меняющее
состояние действие подтверждается отдельно, пока он сам что-нибудь явно не разрешит.

Плюс: не мутирующие инструменты проходят без оценки; нативные `confirm()` уходят человеку;
сбой классификатора трактуется как `high`, а не как разрешение.

### Почему пол всё-таки появился

Изначально зашитого списка опасных действий здесь не было принципиально — казалось, что
это ровно та заготовка, которую запрещает ТЗ. Два живых прогона показали, что рассуждение
было неверным.

Сначала агент обошёл запрет: гейт остановил «Очистить корзину» как необратимое, а агент
добился того же кнопкой «Уменьшить количество», которую классификатор счёл обратимой.
Корзина опустела. Затем агент подтвердил совершеннолетие за пользователя, описав это в
`intent` как «закрыть модальное окно», — и прошёл как `medium`.

Попытки чинить это формулировками промпта упёрлись в нестабильность: одно и то же
подтверждение возраста на идентичном промпте получало то `high`, то `low`. Строить защиту
от необратимых действий на суждении вероятностной модели нельзя.

Запрет ТЗ касается того, как агент **решает задачи**: шагов сценариев, селекторов, подсказок
по элементам. Правила безопасности не помогают агенту ничего достичь — они его ограничивают,
не зная ни одного сайта. Это граница, а не заготовка.

### Как это проверяется

```bash
npx tsx scripts/eval-risk.ts 3     # 11 случаев, 3 прогона
```

Eval меряет итоговое решение гейта, а не мнение классификатора: по отдельности ни один
уровень полной картины не даёт. Случаи взяты из живых прогонов и сценариев ТЗ — оплата,
отклик на вакансию, удаление письма, подтверждение возраста, обход запрета — плюс
контрольная группа обычных действий, которые обязаны проходить молча. Текущий результат:
11/11, стабильно на трёх прогонах.

**Защита от инъекций.** Текст страницы помечен `untrusted="true"`, системный промпт
запрещает выполнять инструкции со страницы. Главное — гейт нельзя снять изнутри модели:
решение принимает код, который страницу не читал. Если классификатор упал, гейт
закрывается, а не открывается (`tests/security.test.ts`).

## Как проверить, что заготовок нет

```bash
# ни одного селектора, домена или названия кнопки целевого сайта
grep -rInE "lavka|yandex|hh\.ru|data-qa|В корзину" src/
```

Единственный адрес в коде — `about:blank`. URL приходят из текста задачи пользователя
или из `href`, прочитанных со страницы в рантайме. Поведение под конкретный сайт нигде
не зашито: системный промпт (`src/agent/prompt.ts`) описывает только способ работы с
произвольной страницей.

## Журнал решений

Подробности замеров — в `RESEARCH.md`, спецификация — в `SPEC.md`.

**Playwright, не Puppeteer/Selenium.** Нужен персистентный профиль (`launchPersistentContext`),
удобная работа с фреймами и авто-ожидания. Плюс из коробки есть `ariaSnapshot`, с которым
было с чем сравнить свою дистилляцию.

**Своя дистилляция, а не `_snapshotForAI`.** Playwright MCP использует внутренний
`page._snapshotForAI()`, отдающий готовые рефы. Проверка прототипа `Page` в Playwright
1.63 показала, что такого метода нет — доступны только `ariaSnapshot` и `ariaSnapshotJSON`,
и рефов они не содержат, то есть кликать по ним нечем. Решение писать свою дистилляцию
оказалось вынужденным и при этом более правильным: она на 3x компактнее a11y-снапшота и
не зависит от приватного API.

**Модальные окна ломают a11y-подход.** Первый замер `ariaSnapshot()` вернул 290 символов.
Не потому что страница пустая, а потому что открытый `[role=dialog][aria-modal]` обрезает
дерево доступности до себя: агент на a11y-снапшоте в этот момент видит только попап.
Отсюда правило в системном промпте — на новой странице сначала распознать и закрыть
модалку.

**`__name is not defined`.** Самый дорогой баг фазы реализации. `tsx` компилирует через
esbuild с `keepNames`, который оборачивает внутренние функции в хелпер `__name`. Playwright
переносит функцию в страницу через `toString()`, хелпера там нет, и дистилляция падает на
каждом вызове. POC на чистом `.mjs` этого не показывал — баг появился именно при переходе
на TypeScript. Лечится шимом, который уходит в страницу строкой, минуя компиляцию
(`Actions.shimEsbuildHelpers`).

**Молчаливые `catch` — худший отказ для агента.** Тот же баг вскрыл вторую проблему:
ошибка главного фрейма глушилась, и агент получал бодрое «интерактивных элементов не
найдено» вместо «страницу прочитать не удалось». Агент пошёл бы принимать решения вслепую.
Теперь провал главного фрейма попадает в наблюдение явным предупреждением.

**Security-гейт чуть не начал кликать не туда.** Первый живой прогон дважды упал в
`stale_ref` на ровном месте. Причина оказалась в нашем коде: перед мутирующим действием
гейт звал `observe()`, чтобы взять адрес и заголовок страницы, а `observe()` снимает и
заново раздаёт все `data-agent-ref`. То есть гейт инвалидировал реф, который модель
только что выбрала. В лучшем случае ошибка, в худшем — реф указал бы на другой элемент,
и клик ушёл бы не туда с уже одобренным намерением. Теперь до действия берётся только
`pageInfo()` (адрес и заголовок, без обхода DOM), тест на регрессию в `browser.test.ts`.

**Ручной цикл, а не tool runner из SDK.** Нужен контроль над историей (прунинг), над
моментом между решением и действием (гейт) и над печатью вызовов в терминал. Плюс
`disable_parallel_tool_use`: браузер последователен, два действия одновременно сделать нельзя.

**Sonnet 5 основной моделью, а не Opus.** Сначала агент стоял на `claude-opus-5`. Шаг
агента короткий: прочитать наблюдение, выбрать элемент, вызвать инструмент. Sonnet 5 на
таких задачах близок к Opus, стоит $2/$10 за миллион токенов против $5/$25 и отвечает
быстрее, а на видео каждая пауза между шагами заметна. Opus 5.5 отпал по другой
причине: он привязывает thinking-блоки к неизменной истории, а клиентский прунинг
(`src/agent/context.ts`) заменяет старые наблюдения заглушками. У аккаунтов, созданных
после 31 августа 2026, такой запрос получает 400. Opus 5 остаётся доступен через
`AGENT_MODEL`.

**MCP: сначала отклонён, потом добавлен вторым входом.** Для собственного цикла MCP
лишний: всё живёт в одном процессе, протокол только усложняет отладку. Основной режим
так и остался без MCP. Второй вход (`src/mcp.ts`) появился по другой причине: API-ключ
Anthropic нужен не всем, а OAuth-токен подписки в собственном приложении использовать
нельзя. Через MCP тот же браузерный слой и тот же гейт работают под Claude Code, и
подписка остаётся там, где её разрешено использовать. Цена описана в разделе
«Режим MCP».

**Провайдер вынесен в конфигурацию.** Изначально модель была зашита константами. Когда
понадобилось гонять агента на GLM через Anthropic-совместимый шлюз z.ai, выяснилось, что
одной подменой `baseURL` не обойтись: adaptive thinking, `effort`, context editing и
prompt caching — расширения Anthropic, и лишнее поле на чужом шлюзе роняет запрос целиком.
Поэтому возможности объявлены флагами и отправляются выборочно. Побочный результат:
агент переносится на любой совместимый шлюз без правок кода.

## Ограничения

- Капчу агент не решает. По ТЗ вход выполняет пользователь; при капче агент зовёт человека.
- Один REPL, одна задача за раз, без очереди и параллельных прогонов.
- Только Chrome. Кроссбраузерность не заявлена.
- Память между сессиями не ведётся: помнит только текущую задачу.
- Лимит 40 шагов на задачу — страховка от зацикливания, а не оценка сложности.
